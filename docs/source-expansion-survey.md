# 영남대 게시판 확장 1단계 조사

조사일: 2026-10-11 (한국 시간). `develop`의 기존 수집기로 공개 목록을 직접 읽어
첫 페이지와 다음 페이지의 호환성을 확인했다. 앱 기능·사용자 DB·배포 EXE는 변경하지 않았다.
원본 HTML과 조사용 스크립트·JSON은 Git에서 제외되는 `.local/board-survey` 등에 보관한다.

## 첫 버전에서 지원할 구조

현재 두 출처에서 사용 중인 공통 HTML 게시판 구조를 지원한다.
학과·사업단 이름별 고정 허용 목록 대신, 영남대 주소와 실제 페이지 구조를 함께 검사한다.
처음 방문한 학과라도 같은 구조라면 등록 가능하도록 한다.

- 목록: `table.board-table`, `tbody`, `b-total-wrap`의 전체 일반 공지 수.
- 행: `b-num-box`, `b-title-box`의 원문 링크, `b-date`의 게시일.
- 식별: 원문 링크의 `mode=view`, 숫자 `articleNo`, 같은 게시판 경로.
- 고정 공지: `b-top-box` 또는 번호 영역의 '공지'.
- 페이지: `b-paging-wrap`, `article.offset`, 한 페이지 일반 공지 10건.
- 문자: 조사 표본의 날짜는 점 구분으로 표시되며 기존 ISO 날짜 변환에 호환.

반도체특성화대학사업단은 `/front/index.php`와 `g_page`/`m_page` 등으로
목록을 구분하는 별도 구조이며, 현재 파서가 목록으로 인식하지 못했다.
별도 수집기를 추가하는 후속 확장으로 남긴다.

## URL 등록 시 내부검사 순서

1. 입력 정리: 양끝 공백 제거, HTTPS 사용, `yu.ac.kr` 또는 그 하위 도메인인지 확인.
   `politics.yu.ac.kr`, `eduhankyo.yu.ac.kr`처럼 학과별 호스트도 포함한다.
   URL 내 사용자명·비밀번호, 비표준 포트와 외부 도메인은 허용하지 않는다.
2. 이번 지원 구조는 쿼리가 없는 `.do` 게시판 경로를 기준 주소로 정규화한다.
   상세보기·검색·페이지 이동 쿼리는 목록으로 되돌린다. 다른 구조에서 필요한
   쿼리를 무조건 지워서 지원한 것처럼 처리하지 않는다.
3. 최종 응답과 이동 대상도 영남대 허용 범위인지 검증한다.
   로그인·접근 제한·홈페이지로 이동한 응답을 공지 목록으로 취급하지 않는다.
4. 첫 페이지를 파싱해 제목·ID·원문 링크·날짜·고정 여부와 일반 행 수를 확인한다.
5. 다음 페이지가 있으면 두 번째 페이지도 확인한다. 링크 존재만으로 성공하지 않고,
   페이지 이동 후 일반 공지 ID가 달라지는지 확인한다.
6. 등록된 기준 URL과 비교해 중복을 막는다. 서로 다른 호스트가 같은 게시판을
   가리키는 별칭 문제는 등록 단계에서 추가로 확인하고, 무조건 합치지 않는다.
7. 출처명과 공지 몇 건을 미리 보여준다. 사용자 확인 전에는 출처나 공지를 저장하지 않는다.

검사에서 구조 미지원, 접속 실패, 로그인 필요, 빈 게시판을 구분해 안내한다.
현재 파서는 빈 게시판을 성공으로 인정하지 않으므로 첫 버전도 등록을 보류한다.
빈 게시판 지원은 잘못된 응답을 빈 목록으로 처리하지 않는 별도 판정이 필요하다.
검사는 목록 최대 두 페이지로 제한하고 원문·첨부파일은 수집하지 않는다.

## 출처명과 로고

조사한 호환 페이지의 HTML `title`에는 게시판 이름과 출처명이 포함돼 있어
기본 출처명 후보를 추출할 수 있다. 추출값은 미리보기에서 사용자가 확인하게 한다.

컴퓨터공학과·SW중심대학사업단·통계학과·정치외교학과·한문교육과에서
출처별 `img-logo.png` 후보 URL을 확인했다. 산학협력단은 이미지 URL 중
푸터 로고 후보만 검출됐다. 반도체 사이트는 SVG 로고를 사용한다.
후보 URL 발견만으로 로고 지원이 완료된 것은 아니다.
원본 이미지의 형식·크기·화면 적합성을 확인한 경우에만 표시하고,
찾지 못했거나 지원하지 않는 형식이면 출처명으로 대체한다.
실행마다 이미지를 내려받지 않고 등록 시 확인·저장하는 방향이다.

## 확정 정책과 후속 구현

- 출처별 최초 수집: 일반 공지 최근 20건 + 고정 공지, ID 중복은 합치고 모두 읽음.
- 일반 공지가 20건 미만이면 실제 존재하는 공지만 등록한다.
- 기존 출처에 쌓인 기록을 20건으로 줄이거나 삭제하지 않는다.
- 이후 신규 수집과 수정 공지 미추적 정책은 유지한다.
- 출처 삭제: 확인창 후 출처 설정과 해당 출처의 공지·읽음·즐겨찾기 기록을 함께 삭제.
  수집 작업과 삭제가 충돌하지 않도록 다음 구현에서 처리한다.
- 처음에는 기존 두 출처와 기록을 이전해 그대로 유지하고 이후 추가·삭제를 허용한다.
- 소식 열 제거, 제목 앞 NEW 표시, 제목 헤더 간소화는 UI 단계에 반영한다.
- 등록 출처가 0개인 상태도 빈 화면과 출처 추가 안내로 정상 처리한다.

다음은 2단계 출처 저장·관리 구조 변경과 기존 DB 이전이다.
이번 단계에서는 최초 수집 숫자를 포함한 앱 동작을 아직 변경하지 않았다.
