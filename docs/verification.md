# 4단계 검증 기록

검증일: 2026-10-02 (한국 시간)

환경: Windows, Python 3.11.9, SQLite 3.45.1. Tkinter 8.6 사용 가능 여부도 확인했습니다.
외부 Python 패키지는 설치하지 않았습니다.

## 자동 검증

실행 명령: `python -m unittest discover -s tests -v`

결과: **23개 테스트 통과**.

- 실제 목록을 축약한 두 출처 표본의 제목·ID·등록일·페이지 이동 분석
- 모의 응답의 신규 공지, 여러 페이지에 걸친 신규 누적, 고정 공지 중복
- 기존 고정 공지가 일반 공지로 바뀌어도 너무 일찍 탐색을 중단하지 않는지
- 최초 30건 + 고정 공지 모두 읽음, 출처별 최초 수집 상태, 신규만 안 읽음
- 재실행 후 읽음·즐겨찾기 복원과 필터 조합
- 기존 공지 내용이 달라져도 저장된 제목·읽음·즐겨찾기 보존
- 수집 중 사용자 상태 변경 보존
- 한 출처 실패, 초기 수집의 중간 실패, 이후 수집의 중간 실패
- 취소 시 미완료 수집 미반영, 중복 수집 거부
- 분석 실패, 저장 실패, 트랜잭션 롤백, 손상/신규 버전 DB 자동 초기화 방지
- 네트워크 재시도 제한, 403/429 재시도 금지

## 실제 게시판 검증

사용자의 실사용 DB와 분리한 임시 DB에서 실행했습니다. 최초 실행 후 같은 DB로 다시 수집했고,
검증이 끝난 임시 DB는 정리했습니다. 상세·첨부·이미지는 요청하지 않았습니다.

| 실행 | 학과 | 사업단 | 전체 소요 시간 |
|---|---|---|---|
| 최초 | 3페이지, 34건 등록 | 3페이지, 32건 등록 | 13.99초 |
| 다시 수집 | 1페이지, 신규 0건 | 1페이지, 신규 0건 | 5.82초 |

총 66건이며 모두 읽음이고, 재수집 뒤에도 총 66건을 유지했습니다.
각 최초 건수는 일반 공지 30건 + 학과 고정 4건 / 사업단 고정 2건입니다.
이는 해당 시점·환경의 실측값이며 매번 같은 속도를 보장하지 않습니다.

2단계 조사에서 받은 각 게시판의 첫째·둘째·마지막 페이지 총 6개에도 파서를 적용했고,
공지 개수와 다음 페이지 유무를 정상적으로 읽었습니다.

## 남은 검증

신규·삭제·수정 및 서버 장애를 실제 학교 게시판에 발생시킬 수 없으므로 해당 시나리오는
모의 응답으로 검증했습니다. 실제 원문 열기, 라이트 모드 화면, 새로고침 버튼,
창 종료 중 작업 취소, EXE 폴더 배포와 바탕화면 바로가기는 UI/패키징 단계에서 검증합니다.
